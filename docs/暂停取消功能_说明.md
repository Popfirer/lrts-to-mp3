## 一、怎么用

转换过程中，操作栏会出现两个按钮（平时是灰的）：

| 按钮 | 行为 |
|---|---|
| **暂停转码** / **继续转码** | 同一个按钮切换。点一下暂停，再点一下继续 |
| **取消转换** | 二次确认后立即中止，按钮变灰 |

- **暂停**：在途的几集转完后停住，不再启动新的一集。点「继续转码」立刻恢复。
- **取消**：
  - 立即终止正在运行的 ffmpeg 进程
  - 清理未完成的 `.__tmp.mp3` 半成品
  - **已转好的 MP3 全部保留**，源文件不动
  - **如果勾了「转换成功后删除手机缓存」，取消后绝不会执行删除**
  - 之后可直接再点「开始转换」续跑（已完成的不重转）

关闭窗口时，如果还有任务在跑，会先自动取消再退出，不留孤儿 ffmpeg 进程。

## 二、语义细节（重要）

### 暂停是「在文件之间」生效，不是立刻冻结

暂停**不会**打断已经在转的那一集。原因：6 个 ffmpeg 进程并行工作，
中途杀掉意味着已投入的解码工作作废。每集约 3 秒，等一下收尾更划算。

实测（8 个 5 分钟音频）：

```
并行转码 8 个文件（6 个 ffmpeg 进程）…
⏸ 已暂停转码，等待在途 5 个任务收尾…
    暂停稳定后 真MP3: 6 -> 6      ← 收尾后完全停住，不再增长
▶ 已继续转码
    恢复后 真MP3: 8
```

### 取消是立即的

```
⏹ 已取消：6 个文件未完成(半成品已清理，源文件保留)。
    取消后 目录: 真=0 假=8 tmp=0
```

取消后线程 **0.0 秒**内退出，无 `.__tmp.mp3` 残留，8 个源文件全在。

## 三、实现方式

### 1. 新增 `TranscodeControl`（线程安全的控制对象）

```python
class TranscodeControl:
    def pause(self) / resume(self) / cancel(self)
    @property paused / cancelled
    def wait_if_paused(self)      # 暂停期间阻塞；被取消时立即返回 False
    def register(self, proc)      # 登记在途 ffmpeg；已取消则立刻杀掉并返回 False
    def unregister(self, proc)
```

### 2. `transcode_to_mp3` 从 `subprocess.run` 改为 `Popen`

原来用 `subprocess.run` 是**阻塞且不可中断**的，无法取消。
改为 `Popen` 并把进程登记到 `TranscodeControl`，取消时 `terminate()` 即可强杀。

### 3. `transcode_in_place` 从「一次性提交」改为「滑动窗口」

**这是关键**。原实现把全部任务一次性 `submit` 给线程池 —— 一旦提交，
就无法阻止后续任务启动，也就无从暂停/取消。

改为滑动窗口（始终维持最多 `workers` 个在途任务）：

```python
def _submit_more():
    while pending and len(futs) < workers:
        f, src, dst, tmp, stem = pending.pop(0)
        futs[ex.submit(_one, ...)] = (f, src, dst, tmp)
```

暂停/取消只需**停止补位**，即可即时生效。

### 4. 在「文件之间」检查状态

```python
while futs:
    finished, _ = wait(futs, return_when=FIRST_COMPLETED)
    ...收结果...
    if control.cancelled:
        continue                 # 不再补位，等在途清空后自然退出
    if control.paused:
        if not control.wait_if_paused():
            continue             # 暂停期间被取消
    _submit_more()
```

### 5. `process_novel` 的阶段边界响应取消

```python
def _bail():
    if control.cancelled:
        stat["error"] = "已取消"
        return True
    return False
```

在阶段 1→2、2→3 之间调用；**删除手机缓存前额外检查**：

```python
if delete_after and stat["out_total"] > 0 and not stat["error"] \
        and not _aborted():          # ← 取消后绝不删手机缓存
```

### 6. GUI 层

- 新增 `btn_pause` / `btn_cancel`，只在转换期间可用（不纳入 `_set_busy` 的统一管理）
- `start()` 创建 `control = core.TranscodeControl()` 并传入 worker
- `toggle_pause()` / `cancel_convert()` 两个处理函数
- `task_done` 消息扩展为 5 元组 `(ok, total, fails, stopped)`，界面可准确显示「已取消」

## 四、返回值变化（调用方注意）

`transcode_in_place()` 的返回字典新增两个键：

| 键 | 含义 |
|---|---|
| `cancelled` | 因用户取消而未完成的数量（半成品已清理） |
| `total` | 本次待转码总数（原来恒为 0，现在正确填充） |

`process_novel()` 的 `stat` 同样新增 `cancelled`；
取消时 `stat["error"] == "已取消"`。
